# Структура проекта Vice City Multiplayer (рабочее название — VC:MP Client)

> Аналог SA-MP / VC-MP для Grand Theft Auto: Vice City.
> Проект — это **не один .exe**, а набор из 4 программ + общий код между ними.
> Этот документ — целевая структура. В репозитории уже создан каркас каталогов (помечена как `[каркас]`),
> остальные файлы будут появляться по мере этапов из [ROADMAP.md](ROADMAP.md).

---

## 1. Из чего состоит мультиплеер — 4 компонента

```
 ┌──────────────────┐        список серверов       ┌───────────────────┐
 │   MASTER-SERVER  │ ◄─────────────────────────── │     LAUNCHER      │
 │ masterserver/    │                              │    launcher/      │
 │ (опционально,    │                              │ сервер-браузер,   │
 │  маленький REST) │                              │ ник, настройки    │
 └────────▲─────────┘                              └─────────┬─────────┘
          │ announce (я жив, IP:port, онлайн)                │ 1) запускает gta-vc.exe (suspended)
          │                                                  │ 2) инжектит client.dll в процесс
 ┌────────┴─────────┐     UDP: синхронизация   ┌─────────────▼───────────────┐
 │      SERVER      │ ◄──────────────────────► │   CLIENT.DLL внутри игры    │
 │    server/       │   пакеты, RPC, чат       │          client/            │
 │ dedicated .exe   │                          │ хуки игры, пулы игроков,    │
 │ + скрипты (Lua)  │                          │ рендер чата/никнеймов       │
 └──────────────────┘                          └─────────────────────────────┘
        ▲                                                  ▲
        └───────────── shared/ — общий код: протокол, пакеты, математика ─┘
                      (одинаковые структуры пакетов на обеих сторонах!)
```

| Компонент | Что это | Технологии | Платформа |
|---|---|---|---|
| **launcher/** | Программа, которую видит игрок: список серверов, кнопка «Играть» | C++ + WinAPI / Qt6 (обсуждаемо, см. ниже) | Windows x86/x64 |
| **client/** | DLL, внедряемая в `gta-vc.exe`. Сердце проекта: хуки, сеть, синхронизация, чат поверх игры | C++20, WinAPI, Direct3D8 hook, MinHook | **Windows x86 (32-bit) — обязательно**, игра 32-битная |
| **server/** | Выделенный сервер, который держат владельцы серверов. Принимает игроков, крутит игровой режим | C++20, ENet (UDP), Lua 5.4 | Windows + Linux |
| **masterserver/** | Каталог публичных серверов для вкладки «Internet» в лаунчере | Любой маленький HTTP-сервис (Python/Go) | Linux VPS |
| **shared/** | Библиотека, линкуется и в клиент, и в сервер: протокол пакетов, BitStream, Vector3 и т.д. | C++20, без зависимости от игры | все |

## 3. Ключевые файлы — зачем каждый (шпаргалка)

### Клиент (самое сложное место проекта)

| Файл | Зачем |
|---|---|
| `client/src/dllmain.cpp` | Игра о нашем коде не знает. Лаунчер инжектит DLL → срабатывает `DllMain` → создаём поток, ждём загрузки игры, ставим хуки. |
| `client/src/game/addresses.h` | GTA VC не имеет API. Мы обращаемся к функциям игры **по адресам в exe** (для версии 1.0 US). Все адреса — в одном месте, чтобы потом добавить поддержку других версий. Источники адресов: реверс (Ghidra/IDA), проект **reVC**, **plugin-sdk** (DK22Pac). |
| `client/src/game/structures.h` | Описание игровых структур (`CPed`, `CVehicle`) как они лежат в памяти игры — чтобы читать/писать позицию, HP, оружие педа. |
| `client/src/game/hooks/*` | Перехваты функций игры (MinHook). Главный цикл — чтобы выполнять свой код каждый кадр; D3D8 — чтобы рисовать поверх; обработка педов — чтобы сетевые педы не жили своей ИИ-жизнью. |
| `client/src/pools/*` | Сервер говорит «игрок №5 в точке X». Пул превращает это в реального педа в игре, двигает его, удаляет при выходе игрока. |
| `client/src/network/sync_*` | Интерполяция: пакеты приходят 20 раз/сек, а кадров 60 — чужих игроков плавно «ведём» между точками, иначе будет дёргание. |

### Лаунчер

| Файл | Зачем |
|---|---|
| `launcher/src/injector.cpp` | Запуск `gta-vc.exe` в приостановленном состоянии (`CREATE_SUSPENDED`), запись пути DLL в память процесса, `CreateRemoteThread(LoadLibrary)`, передача параметров подключения, возобновление процесса. |
| `launcher/src/game_locator.cpp` | Проверка: exe именно версии 1.0 (по размеру/MD5). Под другой exe адреса в `addresses.h` не совпадут → мгновенный краш. SA-MP делает так же. |
| `launcher/src/server_browser.cpp` | Список с master-сервера + query-запросы каждому серверу (онлайн, мод, пинг). |

### Сервер

| Файл | Зачем |
|---|---|
| `server/src/scripting/api.cpp` | То, ради чего люди держат сервера: скриптовый API. В SA-MP это Pawn, в VC-MP — Squirrel. **Предложение: Lua** — проще, популярнее, легче учить комьюнити. Финальное решение — за тобой, см. вопросы в конце. |
| `server/config/server.cfg` | Настройки владельца сервера, формат как привыкли по SA-MP. |

### Shared

| Файл | Зачем |
|---|---|
| `shared/include/shared/protocol/packets.h` | Единый список ID пакетов. Если клиент и сервер разойдутся во мнении о формате пакета — всё сломается, поэтому структура пакета описывается **один раз** здесь. |
| `shared/include/shared/version.h` | Версия протокола числом. При подключении сверяется — старый клиент на новый сервер не пускаем с понятной ошибкой. |

## 4. Что НЕ должно попасть в репозиторий

- ❌ Файлы самой игры (`gta-vc.exe`, `.img`, аудио и т.д.) — это собственность Rockstar/Take-Two. Игрок ставит клиент поверх **своей** копии игры (так работают SA-MP, VC-MP, MTA).
- ❌ Папка установленной игры для тестов — в `.gitignore` (`game/`, `GTA Vice City/`).
- ❌ Собранные бинарники и `build/` — в `.gitignore`, релизы публикуются отдельно (GitHub Releases).
- ❌ Дампы памяти, базы IDA/Ghidra (`.i64`, `.rep`) — тяжёлые и содержат код игры.

## 5. Открытые решения (нужно выбрать до/во время Этапа 1–2)

1. **Сеть:** ENet (простая, надёжная поверх UDP, мой выбор по умолчанию) vs форк RakNet (как SA-MP, но заброшен и тяжёл) vs GameNetworkingSockets от Valve.
2. **Скрипты сервера:** Lua (рекомендую) vs Squirrel (как оригинальный VC-MP) vs Pawn (как SA-MP, но устарел).
3. **UI лаунчера:** нативный WinAPI (лёгкий, но писать долго) vs Qt6 (быстро, но тащит ~50 МБ DLL) vs ImGui-приложение.
4. **Оверлей в игре:** ImGui поверх Direct3D8-хука (быстрый старт для чата/отладки) — почти наверняка да на старте.
5. **Название проекта** и лицензия (MIT / GPL — влияет, можно ли будет закрывать код плагинов).
