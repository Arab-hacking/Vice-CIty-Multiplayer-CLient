# Roadmap — этапы разработки

Принцип: **каждый этап заканчивается чем-то запускаемым**. Не пишем «всё сразу».

## Этап 0 — Исследование и каркас ✅
- [x] Структура репозитория, CMake-каркас, документация
- [x] **Pivot по решению владельца:** цель клиента — **конкретный билд reVC (x64)**, не оригинал VC 1.0
- [x] Сеть: **RakNet wire format** (по PyRakBR, MIT) — собственная реализация в `shared/net/`, без чужих логинов
- [x] Билд reVC получен и разобран: отпечаток + 26 RVA из его PDB (`docs/REVC-BUILD.md`, `client/src/game/revc_addresses.h`)
- [x] Сервер отвечает на offline-ping/SA-MP query, `vc-netprobe`, юнит-тесты фрейминга, CI Windows x64
- [ ] Зафиксировать выбор: скрипты (Lua?), UI лаунчера

## Этап 1 — «Hello, Vice City» (proof of concept) ⏳ следующий
Цель: доказать, что наш код живёт внутри игры.
- [x] DLL проверяет хост reVC.exe, считает базу модуля, резолвит `FindPlayerPed` по RVA, пишет `vc-client.log`
- [x] Лаунчер: выбор reVC.exe (ini), запуск в CREATE_SUSPENDED + инжект x64 DLL
- [x] Хук `CGame::Process` (ручной инлайн-хук под пролог билда): живые координаты игрока в логе ✅ подтверждено на ПК владельца (55k кадров без краша)
- [x] D3D9-оверлей (ImGui + MinHook на EndScene): панель с версией и координатами, F7 вкл/выкл (ждёт подтверждения скриншотом)
- [ ] Горячая клавиша: заспавнить машину перед игроком (`CAutomobile` ctor + `CWorld::Add`)
✅ Критерий: текст поверх игры + машина появляется по кнопке.

## Этап 2 — Сеть и чат ✅ (ждёт финального подтверждения перепиской)
- [x] Свой RakNet-фрейминг + надёжный слой (`shared/net/peer.*`): ACK, повторы, ordered/sequenced
- [x] Сервер: сессии, handshake (версия протокола, ник -> playerId), таймауты, живой онлайн в query
- [x] Клиент в игре: подключение из `vc-client.ini`, статус и серверные сообщения в оверлее, OnFootSync позиций на сервер (10 Гц)
- [x] Чат: ввод в игре по **T** (пед замораживается Teleport-ом на время печати), сервер ретранслирует всем; `vc-bot` для тестов без игры
- [x] Сеть клиента в отдельном потоке — пауза/Alt-Tab соединение не рвут; вежливый Disconnect
- [x] Публичный хостинг: `server.cfg`, проверка maxplayers, [гайд по деплою](DEPLOY-SERVER.md) (Windows/Linux VPS + systemd)
✅ Критерий: игрок в игре переписывается с ботом/вторым клиентом через сервер
(подключение двух «игроков» одновременно уже подтверждено владельцем).

## Этап 3 — Синхронизация пешком (ядро проекта) ★ ⏳
- [x] Сервер ретранслирует позиции: `PlayerStreamIn/Out/SyncUpdate` (протокол v2)
- [x] PlayerPool: спавн `CCivilianPed` через пул игры, ИИ отключён хуком `CPed::ProcessControl`
- [x] Сглаживание движения кукол (Teleport каждый кадр к интерполированной точке)
- [ ] Поворот (heading), анимация бега, HP/оружие в OnFootSync
- [ ] Никнеймы над головами, стриминг по радиусу
- [ ] Спавн/респавн/смерть по командам сервера, выбор скина
✅ Критерий первого шага: бот виден в игре как бегущий пед (ждёт подтверждения скриншотом).

## Этап 4 — Транспорт
- VehiclePool: сервер создаёт машины, клиенты отображают
- Вход/выход, синхронизация водителя (позиция, скорость, поворот-кватернион, HP машины)
- Пассажиры
✅ Критерий: можно кататься вдвоём в одной машине.

## Этап 5 — Стрельба и мир
- Синхронизация выстрелов и урона (bullet sync), смерти от игроков
- Объекты и пикапы от сервера (ObjectPool, PickupPool), чекпоинты/маркеры
- Время и погода от сервера
✅ Критерий: играбельный deathmatch на арене из серверных объектов.

## Этап 6 — Скриптинг и серверная платформа
- Lua API: колбэки + функции (машины, сообщения, телепорты, диалоги/текстдравы)
- Пример gamemode `freeroam.lua`, filterscripts
- RCON (удалённая консоль администратора), баны
- Query-протокол для лаунчера (пинги, онлайн)
✅ Критерий: чужой человек может поднять сервер и написать свой режим по документации.

## Этап 7 — Публичный релиз
- Master-server + вкладка «Internet»
- Установщик клиента (NSIS), автообновление, пакеты сервера Win/Linux
- Базовый античит: проверки скорости/телепортов/оружия на сервере
- Краш-репорты, телеметрия версий
✅ Критерий: публичный тест с внешними игроками.

---

### Что сознательно НЕ делаем в первой версии
- Поддержку exe 1.1/Steam и Definitive Edition (только 1.0 US)
- Синхронизацию трафика NPC и миссий одиночной игры
- Голосовой чат, кастомные модели/карты из клиента (как в MTA) — возможно, позже
