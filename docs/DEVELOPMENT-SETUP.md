# Что нужно для разработки

## Железо и ОС

- **Windows 10/11** — обязательна: клиентская DLL и сама игра — Windows/x86.
  Сервер позже можно собирать и под Linux, но отлаживать клиент можно только на Windows.
- Любой ПК, тянущий VS2022; вторая копия игры/второй ПК (или виртуальная машина)
  очень помогут тестировать синхронизацию вдвоём. Минимум — 2 запуска:
  сервер + клиент на одной машине (подключение на `127.0.0.1:7777`).

## База знаний по внутренностям игры (без этого не взлетим)

- **reVC** — реверснутый исходный код Vice City от комьюнити (исходники гуляют по GitHub-форкам).
  Это главная «документация»: как устроены `CPed`, `CVehicle`, пулы игры, главный цикл.
- **plugin-sdk** (DK22Pac) — готовые заголовки структур и адресов для VC, стандарт для ASI-плагинов.
- **GTAMods Wiki / GTAForums** — опкоды скриптов SCM, описания структур, старые треды VC-MP/SA-MP.
- Исходники/протоколы открытого **MTA** и документации SA-MP — подсмотреть архитектуру синхронизации (копировать код нельзя по лицензиям — смотреть идеи можно).

## Библиотеки (предварительный выбор, зафиксирован в vcpkg.json)

| Библиотека | Для чего | Альтернативы |
|---|---|---|
| **ENet** | Надёжная доставка поверх UDP: каналы, порядок, ретрансмиты | RakNet (как SA-MP, но мёртв), GameNetworkingSockets (Valve, тяжелее) |
| **MinHook** | Хуки функций игры и D3D8 | Microsoft Detours |
| **Dear ImGui** | Чат, отладочные окна, скорборд поверх игры (рендер в D3D8-хуке) | Свой рендер на шрифтах игры (позже, для стиля) |
| **Lua 5.4** | Игровые режимы на сервере | Squirrel (как VC-MP), Pawn (как SA-MP) |
| **spdlog** (опц.) | Логи клиента/сервера | Свой логгер в shared/ |

## Навыки, которые понадобятся (честно)

1. **C++** — уверенно: указатели, память, классы; проект целиком на нём.
2. **WinAPI основы** — процессы, потоки, DLL, `VirtualAllocEx`/`CreateRemoteThread` (инжект).
3. **Базовый реверс** — читать дизассемблер x86 на уровне «найти функцию и её аргументы»,
   понимать calling conventions (__thiscall у методов игры!).
4. **Сети** — UDP vs TCP, сериализация пакетов, интерполяция.
5. Терпение к крашам: неверный адрес = мгновенный вылет игры без объяснений.
   Поэтому с первого этапа — crash-лог и минидампы.

## Первая сборка (когда появится код каркаса)

```powershell
git clone <repo>
cd Vice-City-Multiplayer-Client
# vcpkg в manifest-режиме подтянет зависимости сам при конфигурировании
cmake --preset windows-x86-debug
cmake --build --preset windows-x86-debug
```

## Рабочий цикл отладки клиента

1. Собрать `vc-client.dll` + `vc-launcher.exe` + `vc-server.exe`.
2. Запустить сервер локально (`vc-server.exe` с тестовым `server.cfg`).
3. Запустить лаунчер → сервер `127.0.0.1:7777` → «Играть» → лаунчер инжектит DLL.
4. Краш? Смотреть `client.log` / минидамп → адрес краша → сверять с Ghidra.
   Для глубокой отладки: аттач x32dbg или VS-отладчика к `gta-vc.exe`.
